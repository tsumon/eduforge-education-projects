# EduForge · 学情诊断与分层练习

独立实现《项目实战》3.11.1：导入作业、随堂测、课堂互动 CSV，结合评分标准与课程进度，形成个人和班级诊断、错因证据、补讲清单及带答案提示的三档练习。默认本地运行，不需要模型、API 密钥或联网服务。

这是**规则统计系统**，不是大模型或心理诊断工具。掌握度、人数、薄弱点全部从本次输入计算；系统只引用已有错因标签，不把低分猜成“粗心”“理解能力不足”等原因。内置 CSV、姓名、成绩和题库均为明确标记的合成演示资料。

## 启动

Python 3.10+，在本目录执行：

```powershell
python -m pip install -r requirements.txt
python run.py
```

浏览器打开 [本地应用](http://127.0.0.1:8002)，[交互式 API 文档](http://127.0.0.1:8002/api/docs)。默认只监听本机。可用 `python run.py --port 8002 --data-dir ./my-diagnostics` 指定独立报告目录，或设置 `DIAGNOSTICS_DATA_DIR`；默认 `runtime/diagnostics.sqlite3`。本项目不读写项目一的数据库。

也可运行 `powershell -ExecutionPolicy Bypass -File scripts/start.ps1`。关闭终端或按 Ctrl+C 停止服务。首次界面没有报告；点击“使用合成示例”才生成演示报告，不会把示例当作真实学生数据。

## 完整使用流程

1. 下载示例 CSV、`syllabus.json` 和 `rubric.json`，核对列名、评分规则与进度。
2. 准备 CSV，每行代表一名学生在一个知识点的一次考核，作业、随堂测、互动可放在同一文件中。
3. 导入 CSV，可同时提供本次使用的课程进度、评分 JSON 和班级名。未上传配置时使用 `data/config/` 的默认配置；上传配置只作用于新报告，不会修改服务器默认配置或历史报告。
4. 查看班级知识点、薄弱人数、补讲优先级，打开学生明细查看原始行号、题目、得分、错因及分层练习。
5. 点击题目的提示/参考答案自行核对；练习来自本地人工编写题库，没有生成式题目。下载 Markdown 留存，历史页可重新打开完整报告。

所有新报告初始为“待复核”。教师核对原始成绩、进度和错因后，可填写复核人及备注，点击“标记已复核”；也可撤回到待复核。创建与复核/撤回操作都保存在报告的操作记录中，Markdown 包含这些记录。分层只用于安排练习建议，不自动处罚学生，也不作正式能力评价。复核人是操作者自行填写的标识，不是实名认证。

处理学生成绩时，可设置本地访问令牌后重启服务：`$env:EDU_API_TOKEN='自行设置的长令牌'`。此后所有诊断数据、示例和下载 API 都需要 `Authorization: Bearer <令牌>`；在界面设置中保存该令牌即可访问。令牌只保存在当前浏览器会话，清除设置可移除。`/api/auth/check` 仅返回是否启用验证，`/healthz` 不返回学生资料。未设置令牌时适合本人本机使用；本项目不实现用户组织或个人角色分权。

## CSV 格式与数据处理

必需表头：`学号,姓名,知识点,考核类型,题目,得分,满分,日期`；可选：`错因,备注`。英文列名和常用别名见 [API 说明](docs/API.md)。类型支持“作业/homework”“随堂测/quiz”“课堂互动/interaction”。文本支持 UTF-8、带 BOM UTF-8、GB18030、UTF-16。

- CSV 上限 8MB、50,000 条非空数据行；配置 JSON 上限 256KB、UTF-8 对象。
- 每份报告最多 2,000 名学生、200 个知识点，且“学生数 × 知识点数”不得超过 100,000。知识点包含进度表与 CSV 的并集；在评分与矩阵构建前检查，超限返回友好400，请按班级/章节拆分。
- 得分与满分必须为有限数字，禁止 NaN/Infinity；满分在 `(0, 1,000,000,000]`，得分在 `[0, 满分]`。
- 缺少表头或没有有效数据：拒绝生成报告。单行空值、非法分值、未知考核类型：跳过并报告原始行号。
- 日期错误：保留记录、日期置空并提示。姓名空时显示学号；题目空时使用 `-`，因此建议实际填写题号。
- 学号、知识点、考核类型、题号、日期相同的记录按重复处理，最后一条覆盖前面记录。报告保留实际使用行号。
- 文件名只作为来源信息，上传内容不会写入任意路径；SQLite 只存储报告快照。

## 评分与诊断口径

同一学生、同一知识点，先在每种考核类型内计算 `Σ得分 / Σ满分`，再按权重汇总。默认作业 40%、随堂测 40%、互动 20%；某类型缺失时，对实际出现的类型重新归一。不存在的记录不会补零。同一类型按分值汇总，2 分题与 20 分题不会被当作同权题目。

每人每知识点默认至少需要 2 条**正权重**考核记录。达到要求的知识点才参与个人均分；个人均分是这些知识点的等权平均。班级总均分再对有可评估数据的学生等权平均；单个知识点均分对该知识点可评估学生等权平均。这些数值是本次成绩样本的描述，不等同于考试预测或长期能力评价。

| 状态 | 含义 | 是否计入均分/薄弱/分层 |
|---|---|---|
| assessed | 已授课且记录数达到要求 | 是 |
| insufficient_data | 已授课但证据不足 | 否，掌握度为 null，界面显示 — |
| not_taught | 周次晚于 taught_through_week | 否，即使有预习分数也不判薄弱 |
| unknown_topic | 不在 syllabus 进度表中 | 否，提示核对知识点名称 |

默认分层：低于 60 为基础巩固，60—79.9 为强化提升，80 及以上为拓展挑战。缺少可评估知识点的学生不分层、不分配练习。题目按个人层级、已评估知识点和薄弱优先顺序，从题库选取，默认最多 4 题；找不到对应题目时明确告警，不编造。

班级补讲高优先级：薄弱比例 ≥40% 或该知识点均分 <60；中优先级：薄弱比例 ≥20% 或均分 <70。比例分母是该知识点有足够数据的学生，而非缺失数据的人。报告同时提供人数和覆盖范围。少于 3 名学生时提示不能外推到整个班级。

`syllabus.json` 含 `class_name`、`course`、`taught_through_week`、`topics:[{topic,week}]`；名称不能重复，已授课周次 0—100，知识点周次 1—100。`rubric.json` 可调整三项权重（均非负、和为 1）、分层阈值、最少记录、补讲阈值和练习上限。历史报告保存生成当时的配置快照。题库为 `data/config/exercise_bank.json`。

## 验证

项目不新增生产依赖之外的计算库。核心/服务测试仅使用 Python 标准库；API 测试需要 FastAPI 与 httpx，缺失时跳过：

```powershell
python -B -m unittest discover -s tests -v
# 已安装 pytest 时也可：
python -B -m pytest -q -p no:cacheprovider
```

覆盖数值边界、按分值加权、去重、配置校验、未授课/进度外处理、错因不编造、数据不足不补零、三档题目与答案、报告持久化/隔离、上传/详情/导出 API。所有交付截图均以中文文件名平放在本项目根目录；JSON检查报告保留在 `docs/screenshots/`，截图路径均相对项目根目录。

## 浏览器回归与截图

已有真实截图见 [桌面报告](02_桌面_班级报告.png)、[手机报告](07_手机_班级报告.png)、[学生与练习](04_桌面_学生证据与练习.png)、[人工复核](05_桌面_人工复核.png)。[browser-check.json](docs/screenshots/browser-check.json) 逐项保存实际检查证据，顶层 `passed` 是最终结果；故意上传坏 CSV 产生的400会标注 `expected:true`，不是隐藏的服务失败。

可选自动化脚本 `scripts/browser_check.mjs` 使用 Node.js 22+、本机 Chrome 和 design-taste-frontend 技能的 CDP 辅助库，不需要 npm 安装，也不属于生产依赖。环境变量 `TASTE_SKILL_DIR` 指向该技能目录，默认本机路径 `~/.agents/skills/design-taste-frontend`。

复跑前分别在三个终端启动独立测试库（端口8002的空库仅用于验证首次空态；若正式8002已在使用，请先停止它，再启动这个测试实例，不要清理已有报告）：

```powershell
# 终端1：干净空态；不使用日常数据库
python run.py --port 8002 --data-dir runtime-browser-empty

# 终端2：生成、上传、复核等完整流程
python run.py --port 8004 --data-dir runtime-browser-review

# 终端3：令牌与鉴权下载
$env:EDU_API_TOKEN='diagnostics-browser-review'
python run.py --port 8005 --data-dir runtime-browser-auth
```

另开终端运行 `node scripts/browser_check.mjs`。脚本用真实鼠标/键盘、上传表单和 HTTP 结果验证11项流程，在项目根目录保存1440px桌面及390px手机中文截图（同名已存在时追加“复拍”和时间标识，不覆盖原图）、原始行号证据、复核/撤回操作记录和下载令牌头布尔值；不会把令牌写入URL。失败退出码非零，并保存失败上下文。测试结束用Ctrl+C停止辅助实例；日常使用恢复 `python run.py`。测试库目录为 `runtime-*`，打包和版本管理都排除它们以及所有 SQLite 数据库。

```text
app/core/       CSV、评分配置、规则诊断、SQLite
app/service.py  业务组合、配置快照、导出
app/api.py      HTTP参数和错误映射
static/         原生中文HTML/CSS/JavaScript及本地字体
data/config/    默认评分、进度、人工题库
data/samples/   明确标记的合成CSV
tests/          核心、服务、API测试
scripts/        启动、打包、浏览器验证
```

打包：`python scripts/package.py --group 组名 --name 姓名`，生成 `dist/组名_姓名_学情诊断_教育.zip`，排除运行数据库、依赖和缓存。分数、姓名、报告可能包含教学资料，分享前应自行核对内容。
