# 项目二界面决策

本屏首先回答：哪些已授课知识点值得补讲，依据是哪条考核记录？

对象是考核记录、知识点、学生、分层练习、报告快照；数值均由后端返回，不在前端造样本或默认掌握度。

采用 draw --app analytics 的 framed-sheet：浅蓝灰 L 形框架，白色工作区内收 8px，无投影。品牌保留项目一的 Geist、本地字体与深色按钮。主要数据使用克制的蓝色，其他状态使用文字说明。

独有元素是“掌握度 + 可评估人数 + 课程周次”的同一行：未授课与缺数据保留一行，显示破折号并允许打开证据，不把它们绘制为 0 分。

布局：桌面左栏 204px + 8px 右内收；内容内边距 24px；双列为剩余宽度的 1.55fr / 1fr，间距 16px，两列和间距恰好占满同一内容线。手机折叠为四项底部导航，表格变两行记录。

读数路径：标题与范围 → 四个可追溯摘要 → 知识点及补讲 → 数据质量与练习 → 可展开评分快照。

用户操作：导入 CSV（可附评分/进度 JSON）、明确点击生成合成示例、筛选学生、核对失分证据、逐题展开提示和答案、查看历史与导出 Markdown。
