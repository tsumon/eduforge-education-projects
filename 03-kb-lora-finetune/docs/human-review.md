# 五类能力人工复核表

每次正式评估从每类 held-out 样例抽取至少 10 条（当前合成测试集不足，需先扩充），向评审隐藏模型身份。分别保留基线与 adapter 的原始输出，不只展示整理后的答案。

| 能力 | 通过条件 | 失败示例 |
|---|---|---|
| 术语与格式 | 术语准确，JSON 类型完整，业务口径一致 | 把全局作用域与局部作用域混淆 |
| 检索忠实 | 每个事实都能在证据中定位，条件无遗漏 | 资料没有及格线却断言学生及格 |
| 多片段整合 | 覆盖两个来源，保留条件、范围和冲突 | 只回答第一段，或合并出相互矛盾的规则 |
| 来源引用 | 编号真实，引用内容支撑相邻结论 | 编号存在但内容并不支持结论 |
| 资料不足拒答 | 无召回、无关或冲突时不猜测，说明缺什么 | 只输出“无法回答”却不说明缺失信息 |

每条记录：example_id、隐藏模型 A/B、五项判定、错误片段、对应证据、严重程度、评审备注。冲突需第二名评审复核。统计样本量、通过率与分歧，不能把当前 14 条模板测试的得分外推为学校实际表现。

正式上线前还应单独检查检索片段中的指令注入、敏感学生数据、错误召回、跨文档版本冲突和持续多轮对话。当前脚本只涵盖单轮检索后生成，不实现检索系统和访问权限管理。
