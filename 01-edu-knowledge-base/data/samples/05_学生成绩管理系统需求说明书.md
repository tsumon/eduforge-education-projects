# 《学生成绩管理系统》需求说明书 v1.2

> 本文为 EduForge 合成演示资料，项目、指标与里程碑均为虚构的课程综合项目示例。

## 项目背景与目标

本项目为《Python 程序设计》课程综合项目示例，目标是实现一个支持成绩录入、审核、查询与统计的 Web 系统，替代目前以电子表格人工汇总的方式，减少录入错误并留存操作痕迹。

## 用户角色

系统包含三类角色：教务管理员负责开课、分配教师、审核成绩与发布；任课教师负责录入和提交所授课程的成绩；学生只能查询本人成绩，不能查看其他同学的成绩或班级明细。

## 功能需求

成绩录入：教师可按课程班级逐条录入或通过 CSV 模板批量导入，导入时须校验学号存在、分数在 0 到 100 之间、无重复行。成绩审核：教师提交后进入两级审核，先由课程负责人复核，再由教务管理员终审并发布。成绩修改：已发布成绩不可直接修改，须由教师发起修改申请、填写原因，经管理员批准后生效，所有修改保留修改前后的值、操作人与时间。成绩查询：学生登录后查看本人各课程成绩与绩点，支持导出 PDF 成绩单。统计分析：按课程输出平均分、及格率、分数段分布直方图。

## 非功能需求

系统需支持 200 人并发在线，常规查询响应时间不超过 2 秒；成绩数据保留不少于 5 年；用户密码使用 bcrypt 加盐哈希存储；所有写操作记录操作日志；页面需兼容桌面与手机浏览器。

## 技术方案

后端采用 Python 3.12 与 FastAPI，开发环境使用 SQLite，生产环境切换为 PostgreSQL；前端采用 Vue 3；接口遵循 RESTful 风格并提供 OpenAPI 文档；部署使用 Docker Compose。

## 里程碑计划

第 3 周完成需求评审；第 6 周交付可点击原型；第 12 周完成一期功能上线（录入、审核、查询）；第 16 周完成验收答辩。统计分析模块列为二期。

## 验收标准

核心用例（录入、两级审核、查询、修改申请）通过率 100%；P0、P1 级缺陷清零；并发 200 用户压测下 95% 请求响应时间低于 2 秒；提供用户手册与部署文档。
